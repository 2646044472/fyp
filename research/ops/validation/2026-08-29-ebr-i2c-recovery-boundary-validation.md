# Validation Audit: 2026-08-29 EBR I2C recovery action boundary

## Decision investigated

`EBR`: a low-cost edge node sees an I2C read failure and chooses `retry`, nine-clock bus recovery, target power-cycle, or manual review. The proposed research claim is a finite action-identifiability boundary, not a new implementation of bus recovery.

## Claim under test

For a declared, non-production I2C topology and injected fault set, a policy using a pre-action trace prefix (SCL/SDA levels, transaction phase, ACK/NACK and timeout) can choose a cause-specific recovery action whenever that prefix predicts a different post-action success distribution; otherwise it should return `manual/unknown`. Outcomes would be read success before a deadline, recovery latency, lost samples, and collateral register writes. The stronger claim that this policy beats `always retry`, standard nine-clock recovery, and fixed power-cycle is currently Amber and must be refutable.

## Assumption and identification audit

1. **Fault state is not observable from the proposed prefix alone.** `NACK`, timeout, and static line levels are many-to-one observations. An unplugged target (no pull-down) can yield a NACK with both lines high; an address-phase interruption can yield SDA low while SCL high; a permanent external SDA clamp can have the same static state as a slave-held line. A policy can select a prior- or cost-optimal action, but cannot claim cause identification from the prefix.
2. **Nine clocks are not universally benign.** Linux's fault-injection documentation, current page sections “Incomplete transfers” and “incomplete_write_byte”, warns that additional SCL pulses can cause random data to be written to register 0x00; the bus may also contain devices that self-recover. Therefore `collateral register writes` must be an explicitly checked outcome and the experiment must use a sacrificial target with a read-only or reset-safe register map.
3. **A second trace changes the question.** A logic analyzer is suitable as ground truth, but if the deployed policy sees both source-side and host-side traces, the claim becomes multi-vantage diagnosis and directly approaches SentryBus. A single host-side GPIO trace cannot establish the physical source of a stuck line.
4. **Action utility needs a declared application loss.** “Recovery success” alone makes power-cycle look worse only because it is slower. Define a fixed observation period and costs for missed samples, latency, energy, and collateral writes before tuning. Otherwise an action policy can be post-hoc optimized.
5. **Fault injection must be repeatable.** Use separate open-drain MOSFET clamps for SDA/SCL, a controllable target reset/power switch, and an instrumented target firmware that stops after address ACK, after a write-byte ACK, or holds a line. A loose jumper or unplug event is not a reproducible state label.
6. **No guarantee transfers across devices.** BME280, SHT31, and VL53-class targets differ in reset behavior, clock stretching, write side effects, and self-release. The honest unit of analysis is one declared topology plus held-out runs/fault timings, with cross-target transfer an optional negative result.

## Strongest simple baseline

The strongest baseline is a deterministic staged driver, not a learned policy:

`read with bounded timeout -> one retry if bus is free -> standard Linux/generic nine-clock recovery if SDA is low and SCL can toggle -> target reset/power-cycle after a fixed failure count -> manual/unknown`.

Evaluate it against `always retry`, `always nine-clock`, `always power-cycle`, and an oracle that knows the injected fault. If the staged driver matches any proposed policy on success, p95 recovery latency, lost samples, energy, and collateral writes, the EBR contribution is eliminated. A learned classifier must also beat a hand-coded decision tree under a predeclared action-cost function; otherwise model complexity is unjustified.

## Contrarian result

The proposed passive cause-specific policy is not identifiable. Two worlds can emit the same prefix `SCL=1, SDA=0, NACK/timeout`: (A) an external permanent SDA clamp, where clocks and power-cycling the target do nothing; (B) a target left mid-transfer, where clocks may release SDA; (C) a target that is unpowered or unplugged, where power-cycling is ineffective until reconnection. The policy therefore cannot guarantee the beneficial action from the declared prefix. The only defensible positive result would be conditional: for a fixed topology and fault generator, some *additional observable* (e.g., whether SCL toggles under a bounded probe, or a target reset-status GPIO) changes the post-action success distribution. That probe is an intervention and must be counted in latency and risk.

## Feasibility audit

- **Hardware:** ESP32/RP2040 or Raspberry Pi GPIO, one BME280/SHT31-class I2C target, MOSFET or analog switch for target power, 4.7-10 kOhm pull-ups, and a low-cost 8-channel logic analyzer are sufficient for a benchtop demonstrator. The analyzer must be validated against requested sample count; SentryBus reports silent truncation as a real threat (PDF pp.6-7).
- **Faults/labels:** open-drain SDA/SCL clamps and target firmware-controlled incomplete transfers provide repeatable labels; unplugging and random jumper motion should be excluded from the primary table. Ground truth is an analyzer-side marker or second trace, never the policy input.
- **Data/compute:** 100-500 repetitions per fault/timing cell and a small tabular policy fit on the MCU/RPi are feasible. No public dataset or GPU is required; the result is a measurement protocol and boundary map.
- **Ethics/safety:** non-production electronics only, no personal data, no safety actuation. Use current-limited supplies and a sacrificial/read-only target to avoid damaging devices.
- **Time:** a demo can show injected fault, trace, action and recovery by 2026-12. Robust held-out target/device/timing cells and uncertainty analysis fit 2027-H1. Instrument availability and exact budget remain `[GAP]`.
- **Feasibility kill:** if the chosen MCU cannot switch I2C pins to GPIO or the analyzer cannot capture at the selected bus rate, the experiment reduces to a software simulation and loses the physical edge story. Confirm these before purchasing around the direction.

## Decision

`EBR` is **PIVOT / Amber**, not PROMOTE. The recovery mechanism, wire-level fault classes, and monitor-then-reset/isolate action family are already occupied by Linux/TI/NXP and US20250068503; SentryBus also occupies the generic multi-vantage observability protocol. A passive trace-prefix policy cannot identify all causes. Continue only as a bounded, non-affirmative measurement study with a pre-registered ambiguity map and matched-cost simple baselines. Promote to an FYP direction only if a cheap, independently measured observable or a counted probe changes post-action success on held-out cells and beats the staged baseline; otherwise retain the negative indistinguishability result and pivot away from I2C recovery.
