# Validation Audit: 2026-08-31 FSD-WIT removable-media power-cut witness

## Decision investigated

Whether **FSD-WIT** should advance from Amber HOLD to an undergraduate-FYP research direction: for a pre-registered `(host, card, filesystem, log layout, cut waveform)` configuration, an append/prefix journal and post-reboot checker allegedly estimate a held-out upper bound on `retain AND recovered prefix is invalid`, retain more records than `always-unknown`, and reveal non-transport to another COTS microSD card.  POF-ADM is examined only insofar as it could add information to that decision.

## Claim under test

The proposed scientific object is not a new journal.  It is an empirical *evidence boundary*: after a real sudden power cut, a host-visible checker would support a false-retain upper bound for a named configuration and demonstrate when that bound does not carry to another card.

This audit tries to kill that object, not the useful engineering practice of logging a sequence number, checksum, and commit marker.  The relevant endpoint is specifically the local post-reboot `retain / unknown` decision, rather than mountability, reset cause, or a generic power-loss benchmark.

## Assumption and identification audit

1. **The checker is simultaneously the policy and the lab oracle.**  With synthetic records whose expected sequence/payload digest is available outside the card, a reboot checker can directly scan the valid prefix.  The simple correct policy is then `retain exactly records passing the declared prefix/commit predicate; mark every other record unknown`.  It does not need an estimated false-retain model.  Any observed false retain is a failure of that predicate, a checksum collision, or a mismatch between its oracle and the definition of a valid record.  Thus an empirical rate table tests the storage/protocol configuration; it does not create a new evidence mechanism.

2. **The lab's synthetic oracle cannot silently become a real sensor-record guarantee.**  If the deterministic expected payload/digest is removed, a card-local checksum only establishes byte self-consistency, not that a sensor value was actually acquired, correctly serialized before loss, or semantically correct.  If the deterministic external expected value remains, the test contains an external truth oracle unavailable to a real logger.  FSD-WIT may claim only synthetic, storage-prefix recovery.  Extending it to sensor-record admissibility is unidentifiable from host/card observations alone. [KILL]

3. **`fsync`/rename do not define a single physical cut state.**  POSIX and Linux distinguish file data/metadata from a containing-directory entry; application recovery depends on explicit ordering.  CrashMonkey likewise treats crashes in the middle of an operation as having several valid recovery states and bounds its main tests to persistence points.  Therefore a clock offset relative to a userspace call is not sufficient to enumerate the card's internal state.  A physical waveform/cut point must be recorded independently, and all claims must be conditioned on that waveform and the full write history. [K]

4. **A confidence bound requires a sampling claim, not merely a held-out split.**  NIST's exact-binomial material takes binary trials and a specified confidence construction; NIST TN 2045 requires a predefined threshold, sample size, and acceptance criterion for a binary response.  FSD-WIT currently names no target rate, confidence level, sample-size calculation, randomization unit, or stopping rule.  In particular, with zero observed false retains, a 95% one-sided binomial upper limit is approximately `1 - 0.05^(1/n)`: about 2.96% at 100 independent cuts, 1.00% at 299, and 0.10% at 2,995.  Those numbers do **not** cover non-random offsets, different discharge curves, aged card state, or another card. [KILL] the word `upper bound` unless this scope is written before data collection.

5. **The proposed transport experiment has the right negative interpretation but cannot establish the positive one.**  SanDisk's current industrial-card white paper says consumer cards can undergo unannounced controller/NAND/firmware configuration changes under the same brand/model name, whereas a defined BOM is a distinct industrial property.  Consequently a bound for card A neither identifies a retail-model population nor becomes a bound for card B.  One failed transfer is honest negative evidence; one successful transfer is only two sampled devices. [K]

6. **POF-ADM adds no independent record-validity witness.**  A comparator/reset marker can stratify the same cut experiment but cannot observe the FTL's final state or a sensor's semantic value.  Nordic's documented power-failure warning is preparation-time/device-write behavior, while the SD Association documents cache/background maintenance and says data are not guaranteed until a supported flush completes.  Unless comparator features reduce false retain at a prespecified equal-or-lower unknown rate over the same external recovery oracle, POF-ADM is redundant instrumentation. [KILL as standalone.]

## Strongest simple baseline

**B0: preallocated append-only fixed-size slots plus two-phase validity marker, checksum/sequence scan after reboot, and `unknown` for every slot without a complete valid marker.**  On a POSIX host, the persistent transition must include the needed file and directory synchronization; on FatFS, use its documented immediate-sync option where applicable.  B0 issues no statistical prediction: it accepts the verified prefix and rejects the rest.  Its false-retain rate in the synthetic-prefix definition is zero by construction *unless its in-card evidence predicate itself is falsified*, in which case that falsification is exactly the standard power-cut test result.

FSD-WIT cannot beat B0 on false retains without accepting a record B0 calls incomplete.  If its benefit is only fewer `unknown` records, it must beat B0's retained-prefix/latency/energy frontier on a frozen configuration; no distinct action or mechanism presently explains how.  The alternative `always-unknown` likewise supplies the trivial zero-false-retain lower control.  This is the candidate's declared kill condition, but it is stronger: B0 is not merely a baseline to run later; it implements the entire valid-prefix decision now.

## Contrarian result

**[KILL] FSD-WIT is a narrowly useful configuration-characterization/replication experiment, not a defensible primary FYP direction as formulated.**  Its claimed witness is either tautological for synthetic data (the same valid-prefix scan both defines and decides retention) or insufficient for real sensor data (a storage checksum cannot establish acquisition truth).  Real power-fault plus recovery-oracle studies, bounded black-box crash testing, and contemporary application-level crash-state testing already occupy the mechanism and evaluation family.  The remaining difference is an inexpensive microSD fixture and an honest report that card A did or did not resemble card B.

The planned negative result remains worth preserving: a fully preregistered power-cut dataset can show that B0's recovery behavior changes with card, age, write history, or waveform.  It should be framed as an appendix/benchmark or a teaching/reproducibility artifact, not as an upper-bound or transportability contribution.

## Feasibility audit

| Item | Status | Audit result |
| --- | --- | --- |
| Hardware | [C] feasible as a bench replication | An ESP32 (firmware in internal flash) plus separately switched microSD rail is less destructive than cutting a Pi boot card.  But switching only the card rail emulates abrupt card removal, while switching the whole system also destroys host timing and reboot state; these are distinct fault models.  A MOSFET alone does not document the delivered discharge waveform.  An independently powered scope/logic/power recorder is needed to label actual voltage/current timing. |
| Data/ethics | [K] feasible | Synthetic deterministic records and lab-owned media avoid personal data and production impact. |
| Time | [C] feasible for a bounded appendix, not for a persuasive transport claim | A fixed `n` physical-cut study plus rebuild/reformat/recovery automation fits a year.  Factorial coverage over card unit, model/BOM, age/endurance, filesystem, log layout, temperature, voltage fall, request size, and cut phase does not. |
| Statistics | [GAP] not yet feasible as a bound | Target false-retain rate, confidence, power, randomization, independence rationale, replacement protocol after card damage, and failure stopping rule are absent.  Without them results are descriptive counts. |
| Cost/safety | [GAP] conditional | Cards and an MCU are inexpensive, but a supervised, independently measured power-cut fixture and sacrificial media are necessary.  Do not cut a system boot medium repeatedly; isolate the test medium and use a recoverable image procedure. |

## Decision

**KILL as a primary FYP research direction.**  Preserve only a small, clearly labelled physical power-cut/recovery dataset as a negative-result or reproducibility appendix: it can report configuration-specific recovery behavior and non-transport, but must not claim a general durability certificate, a cross-card upper bound, sensor-record admissibility, or a new crash-consistency mechanism.

**POF-ADM: PIVOT to instrumentation only.**  Run it only if a preregistered equal-unknown-rate comparison can show incremental predictive value over B0's post-reboot scan; otherwise report it as a null measurement and stop.

KILL
