# Validation Audit: 2026-08-31 BIA-1 compound-domain attribution sufficiency

## Decision investigated

Whether BIA-1 can be a defensible CS FYP: using only licensed public data and a frozen offline palm matcher, determine whether a cross-domain verification-performance difference is attributable to a named device/sensor factor, is only a broad-domain association, or is attribution-insufficient. This audit contains no authentication attack, bypass, or live-service procedure.

## Claim under test

The proposed contribution is a predeclared certificate with three outcomes: `factor-attributable`, `broad-domain-only`, or `attribution-insufficient`. It assumes a frozen matcher, identity-disjoint evaluation, a frozen operating point, recorded nuisance variables, conditional estimates, support checks, and a sensitivity analysis. The current proposed substrate is X-Palm v2's paired scanner/smartphone data.

The decisive question is not whether a compound cross-domain EER can be calculated. It can. The question is whether public evidence identifies the counterfactual effect of changing one named device/sensor factor while holding the relevant capture, ROI, and subject conditions fixed. A conditional association is not such an effect without a defined factor, measured covariates, overlap, and a defensible design assumption.

## Assumption and identification audit

For a factor-specific result, BIA-1 would need all of the following before any score analysis. Failure of any item must produce `attribution-insufficient`; it must not be repaired by fitting a larger matcher or a more elaborate regression.

| Required condition | Status on the inspected X-Palm record | Consequence |
| --- | --- | --- |
| A single, well-defined factor `v` whose intervention is meaningful, for example a declared camera/sensor configuration rather than the entire personal-phone capture chain | [KILL] The scanner bundle changes camera/IR and six controlled illuminations; the phone side is participant-owned and compound. `scanner` versus `phone` is not one sensor intervention. | A contrast of these labels is a broad-domain contrast, not a device/sensor effect. |
| Per-sample, released ground truth for `v` and each proposed conditioning variable `u`, including device model, capture/session, condition, raw-to-ROI processing path and any factor used in exclusions | [GAP] The paper says a hardware survey including smartphone model was collected, but the public README schema exposes X-Palm image names as `{id}_{side}_{condition}` and the signed-access data/datasheet have not been supplied. | The audit cannot assert that a licensed user receives the required columns, their completeness, or their permissible use. A model inferred from pixels is not ground truth. |
| Support/positivity: observations from both levels of `v` within relevant `u` strata, with enough repeated trials for a stated estimand | [KILL] The 81 paired participants have one controlled scanner setting and their own smartphone; 10 structured plus 5 random phone captures change condition while retaining that person's device. No inspected source establishes subject/session repetitions across devices or a cross-classified device x pose/light/distance/ROI design. | Conditional estimates of a device effect require extrapolation in unsupported cells. A sensitivity interval cannot turn absent support into identification. |
| A design assumption that blocks device assignment/ownership from unrecorded causes of the scores, or a controlled crossover/randomised intervention | [KILL] Phone choice and participant-driven capture are observational; the paper deliberately targets realistic compound variability rather than a controlled hardware experiment. | Even a future device-model column would provide an observed association unless a stated causal design/assumption is separately justified. |
| Frozen verification definition: mated/non-mated trial construction, identity-disjoint development/test split, threshold/FAR rule, uncertainty unit and no tuning on the claimed test cell | [GAP] X-Palm publishes general recognition protocols and scores/EER, but BIA-1 has not registered its exact pair construction, target parameter, subject-level resampling unit or minimum cell counts. | A difference in EER alone is not a factor attribution certificate. Threshold-dependent error rates require the threshold and reference composition to be stated. |
| A legal permission to derive/store scores and publish aggregate audit results under the actual signed EULA | [GAP] X-Palm says access requires a signed non-commercial EULA and prohibits redistribution, re-identification and commercial use. The complete signed terms and issued data schema were not available to inspect. | Academic access is not evidence that this particular derived-score audit, metadata use, or result release is authorised. |

The most important failure is structural. For paired participants, holding identity fixed compares `scanner + controlled illumination + controlled pose/ROI chain` with `personal phone + participant capture + compound conditions`. For the phone-only condition studies, holding the phone fixed can estimate selected *condition associations* within that phone, but it cannot estimate a different-device effect. The public record therefore supports neither exchangeability nor overlap for the named-factor claim.

An honest sensitivity analysis would have to state a numerical bound on the contribution of unmeasured capture/ROI conditions. With no supported device comparison, a sufficiently large unmeasured contribution can reverse either sign of the alleged device effect. Thus the interval is not an empirical certificate of a sensor effect; it is an assumption-indexed statement that must end as `attribution-insufficient`.

## Strongest simple baseline

Use the ISO-style **broad-domain report** as the baseline: freeze one matcher and threshold; construct the declared identity-disjoint mated/non-mated trials; report scanner-versus-smartphone score/error differences with subject-level uncertainty; tabulate only released condition labels and cell counts; publish a factor-support manifest; and emit `broad-domain-only` whenever the claimed factor is not measured, not supported in both conditions, or not legally usable. This baseline already produces the only honest X-Palm conclusion and needs no new causal certificate. A BIA-1 implementation that reaches the same output has added reporting automation, not a falsifiable CS mechanism.

## Contrarian result

The charitable case for BIA-1 is that an explicit `attribution-insufficient` output could stop misleading device/sensor claims. That is useful project governance. It does not survive as a primary FYP contribution because ISO/IEC 19795-10:2024 already requires the relevant preplanning, controls, uncertainty and disclosure of non-unique attribution, while X-Palm fails the proposed positive branch. The nearest modern shift papers make the same point from the ML side: shift detection/decomposition is not a physical root-cause identification result without measured, supported metadata and design assumptions.

## Feasibility audit

- **Data/EULA:** [GAP] The X-Palm paper says that the full EULA and datasheet are available through its access process and requires a signed agreement. This audit could inspect only the paper/repository's access description, not an issued agreement or data package. Do not presume that processing scores, using hardware-survey fields, retaining derived tables, or publishing aggregates is allowed.
- **Schema:** [GAP] The paper says the intake survey included smartphone model, but this is not proof that the released package exposes a row-level, complete, linkable device field with capture/session/ROI provenance. The public README's X-Palm filenames only expose identity, side and condition. Requesting access cannot be counted as satisfying the data gate until the received schema is inspected.
- **Identification:** [KILL] 81 paired people is not a controlled repeated-device study. A matched scanner/phone pair removes part of between-person variation, but leaves scanner-versus-personal-phone capture bundles inseparable. The smartphone condition repetitions hold device fixed, so they cannot create device overlap.
- **Endpoint:** [KILL] The research actor's decision is to avoid an unsupported intervention on hardware, template protection, or matcher. On X-Palm, the protocol can only say that the benchmark has a broad compound domain difference. That is an appropriate caveat to an existing benchmark result, but it has no distinct action, system behavior, or outcome beyond ordinary evaluation reporting.
- **CS-FYP contribution:** [KILL] The residual task is a checklist/manifest generator plus standard confidence intervals and a refusal rule. It can be retained as an appendix or mandatory gate for any biometric benchmark experiment, but should not consume the FYP's research slot.

Queries run on 2026-08-31: `causal dataset shift explanation attribution root cause analysis benchmark 2024 paper`; `site:arxiv.org causal performance degradation root cause analysis dataset shift 2025`; `site:arxiv.org causal dataset shift attribution confounding identification 2026`; `X-Palm dataset EULA metadata schema paired scanner smartphone 81 github 2026`; `dataset shift root cause metadata causal 2025 machine learning paper`; `causal attribution performance gap dataset shift paper`; `distribution shift decomposition performance gap causal 2024`; `biometrics dataset documentation data card benchmark reporting confounding device sensor 2024 2025`.

Failed/unresolved: no accessible primary work was found that uses the exact BIA-1 literal certificate labels on palm data; this is not novelty evidence. The public X-Palm paper says a complete EULA/datasheet exists, but the signed agreement and released row-level schema were not inspectable through the public repository/access page, so permission for score/metadata processing and the presence/completeness of device/session/ROI fields remain [GAP]. No inspected X-Palm source establishes repeated captures of the same identity on multiple phone models under cross-classified nuisance conditions. No causal sensitivity bound was supplied by BIA-1; without a justified bound, a sign-reversal test would be assumption-driven rather than an empirical sensor result.

## Decision

**KILL as a standalone FYP candidate.** Retain BIA-1 only as a mandatory biometric preflight/appendix: on X-Palm it may report `broad-domain-only` or `attribution-insufficient`, never `factor-attributable`. Do not promote it by adding a dashboard, a Pi runtime measurement, a larger matcher sweep, or a new label name. A future revisit would require a separately licensed controlled/crossover data resource with released per-sample factor and provenance metadata, a registered causal estimand and support thresholds, and a contribution beyond the ISO-style reporting baseline.
