# Validation Audit: 2026-09-27 Palm candidate gates

## Claim under test

The strongest remaining possible question is not a new Palm algorithm: under a frozen physical Palm payment path, can (a) an enrollment choice or added enrollment visit change a later untouched transaction outcome, or (b) an intervention/modality/physical PAD change an all-start action endpoint beyond fixed Palm controls at equal opportunity and cost? The null alternative is that current evidence supports only an engineering prerequisite or descriptive negative audit. No claim of global novelty is tested or made.

## Assumption and identification audit

1. **Enrollment distinctness is still unproven.** The active round-25 correction says the payment UI's five enrollment samples are repeated calls to the latest camera frame without an explicit wait for a fresh frame; the current code confirms `palm_payment_ui.py` calls `camera.frame()` in a list comprehension, and `workflow.enroll_user()` stores feature arrays plus a sample count only. `CameraFeed.frame()` now records a frame ID and time for the last served frame, but enrollment does not retain these contexts, presentation IDs, visit IDs, rejected attempts or failure reasons with template versions. Thus five stored embeddings are not five distinct presentations, and even a recorded ID would not establish cross-visit separation.
2. **Checkout trace lineage is incomplete for a research estimand.** `workflow.py` logs capture context after a separate `frame()`/`capture_context()` call. The per-camera served context is shared mutable state; concurrent requests can overwrite it between calls. The logged ID may not be atomically bound to the exact returned image. The trace has ROI status/reason/quality, identification status, score, second score, outcome and timings, which is useful instrumentation, but the candidate still needs atomic image-context binding, an eligible-start definition, independent owner/unknown labels, stable session/visit IDs and every failed start. The matcher currently emits one selected identity, but the pipeline log alone cannot define whether a participant was authorized for that mock account.
3. **Open-set rare-event precision is outside a small smoke cohort.** If zero wrong actions are observed among `n` independent unknown people/episodes, the exact one-sided 95% binomial upper bound is `1 - 0.05^(1/n)`: about 13.9% at n=20 and 3.0% at n=100. Repeated probes from one person do not create independent people. These bounds do not prevent a descriptive audit, but they defeat “rare wrong-debit risk improved/safe” language at FYP-scale cohorts unless a substantially larger/appropriately sampled evaluation is feasible.
4. **Available public/local data do not satisfy the action endpoint.** PalmBigDataBase's present workspace manifest describes an archive used for an ignored 20-identity × 10-image smoke subset and leaves source terms unresolved. The CASIA multispectral archive contains apparent six-band images and also has terms unresolved; it is not a synchronized Pi capture or terminal action log. Palm-ID and X-Palm can support benchmark comparisons under their protocols, not prove local app reachability/action effects. X-Palm's paired-identity dataset is valuable direct neighboring evidence; access is still governed by its academic terms and its design is not the proposed three independent transaction visits.
5. **NIR is a sensor profile, not yet a valid missing-modality recognition variable.** The README describes separate RGB and NoIR-plus-IR capture profiles, prevents cross-profile template use, and explicitly disclaims vein/liveness inference. The app has no paired NIR identity matcher, synchronized sensor path, or missingness assignment mechanism. Current setup lacks verified repeated vascular evidence, exposure/registration characterization and an equal-cost matched second-VIS baseline. `NIR-MISS-X` cannot proceed from the file archive alone.
6. **Ethics/apparatus gates remain real.** Repeat-visit enrollment retains biometric templates across time and requires explicit consent, institutional route, deletion/retention and versioning rules. Physical PAD requires authorized print/display materials, lineage tracking, bona-fide balancing and a live presentation route; do not convert public/cropped attacks into a claim about the actual sensor path. No actual payment or production-security inference is permitted by the active charter.

## Strongest simple baseline

Run the actual frozen VIS path first and compare only the surviving question against its strongest static controls: (1) best-quality single enrollment frame; (2) fixed diverse/multi-template enrollment at the same template/search budget; (3) same-session-only; (4) two-visit enrollment without the candidate selector; (5) refusal/re-enrollment; and (6) for physical capture, current fixed prompt, fixed one-retake by quality/margin, and conservative unknown. `NIR-MISS-X` additionally needs VIS-only, fixed paired VIS+NIR, and fixed second-VIS at matched total opportunities/time/energy. `PA-FULLPATH` needs no-PAD, quality/score rejection and fixed recapture before any PAD-control comparison. Person- and session-block splits, independent identity/authorization labels and terminal action outcomes are required. A cropped-image rank improvement, one person repeated many times, or zero errors in a small pilot cannot beat these baselines.

## Contrarian result

The tempting claims all collapse on the first practical comparison: Palm-ID has already combined mobile capture, ROI, open-set search, quality reject/recapture and time-separated performance; a hand guide itself is old; VIS/NIR fusion is already recognition/PAD territory and not a guaranteed gain; and GBU-Palm directly supplies recent RGB/NIR physical print/replay PAD. “Measure the transaction” can be meaningful engineering and perhaps a bounded external-validity audit, but no candidate presently has the frozen all-start data or independent labels that would make its residual distinction real. The best counter-argument is that these papers do not report this exact Pi UI's mock-debit path or three-stage charged enrollment policy. That is true but only creates an apparatus-specific experiment, not a defensible thesis contribution absent an adequately powered, permitted result that beats the stated simple arms.

## Feasibility audit

- **Current implementation and logs:** the files provide a local mock payment workflow, open-set thresholding and JSONL logs. The only inspected runtime log, `code/palm_demo/runtime/logs/2026-08-31.jsonl`, has five events (two enroll, three verify) and no `frame_id`, `visit_id`, `roi_status`, or transaction `result` field; it is not an all-start Palm Payment dataset. No consented independent roster was found. Current checkout code can log useful stages, but enrollment sample/session provenance is absent, and image/frame trace association is not atomic under concurrent requests. The five-image enrollment loop repeats `camera.frame()` without waiting for a fresh presentation.
- **Current data:** local PalmBigDataBase and CASIA-Multi-Spectral archives are present but permission/terms are [GAP]. The documented processed PalmBigDataBase 20×10 subset is development-only. Neither substitutes for three separated physical payment visits; CASIA image bands do not provide an app's actual missing-modality capture/action endpoint. X-Palm provides a stronger public/controlled research route if terms permit, but it is not the payment path and has only paired scanner/mobile domain collection as specified in the paper.
- **Participants/statistics:** the 2026-09-24 gates require repeat consentees, three disjoint visits and independently enrolled unknowns; none are confirmed. Small numbers can support instrumentation or variance discovery, not rare false-action bounds or stable person-held-out modality effects.
- **Hardware:** the README documents RGB and NoIR+IR as separate profiles, explicitly rejects cross-profile matching, and says auto-exposure/white-balance are unsynchronized if both cameras run. There is no evidenced synced paired rig, captured vascular signal, energy protocol or fused classifier. Treat the NoIR sensor as a second observation channel, not as proof of vein/liveness.
- **Ethics/apparatus:** obtain the institution/supervisor route and explicit data-retention/deletion/return-visit permission before longitudinal biometric capture; physical attack lineage and any test materials also need approval. These are hard prerequisites to `E-BOUND-X` and `PA-FULLPATH`, not paperwork that can be replaced by software tests.
