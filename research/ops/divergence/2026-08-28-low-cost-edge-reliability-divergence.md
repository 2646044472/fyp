## Top two formalizations

### C1: calibration-age-aware selective CO2 alert

- **[D]** At time `t`, an edge node observes `x_t = (z_t, e_t, a_t)`: cheap-sensor reading `z_t`, available environmental telemetry `e_t`, and calibration age/history `a_t`. Reference concentration is `y_t`; action is `d_t in {alert, no-alert, inspect}` around a predeclared threshold `tau`.
- **[A]** A calibration residual process estimated on prior chronological data is informative about `P(y_t > tau | x_t)`. This is not established for new locations, rooms, or sensor models.
- **[T]** On held-out sensors and future time blocks, a policy that calls `inspect` only when its estimated action risk exceeds a fixed budget `q` has a lower false-safe rate than calibrated-point-threshold and fixed-margin abstention at no greater inspection rate and bounded alert delay.
- **Observable outcome:** reference-labelled false-safe and false-alert rates, inspection/coverage, decision delay, and conditional calibration across sensor, season, and age bins.
- **Counterexample:** Two future residual processes yield the same `(z_t,e_t,a_t)` history yet cross `tau` in opposite directions. No policy using only these observables can be uniformly correct; a reference check or conservative abstention is required.
- **Negative-result value:** quantify the inspection-rate lower bound needed for a false-safe target, or show calibration age/environment cannot predict decision error beyond a fixed margin. Either result rejects the proposed information set rather than hiding it with a model change.

### C3: resource-informed edge-service failure suspicion

- **[D]** At heartbeat `t`, observe `o_t = (inter-arrival latency, memory pressure, CPU, I/O, temperature)`; latent state `s_t in {healthy, transient-resource-stress, fail-slow/fail-stop}`; action `d_t in {continue, suspect/observe, failover}`.
- **[A]** The local resource signals provide information that separates transient contention from sustained failure on a specified device/workload/fault family. It is expressly not assumed across arbitrary hardware or adversarial/Byzantine faults.
- **[T]** A fixed-compute state machine using `o_{t-k:t}` weakly improves the static-timeout and percentile-timeout Pareto frontier for false failovers and time-to-detect, on a pre-registered held-out device/workload/fault split.
- **Observable outcome:** confusion by injected state, false failovers, time-to-detect, p95 heartbeat/jitter, monitor CPU/RAM, and service availability.
- **Counterexample:** If a real fail-slow and a resource-stressed healthy service have identical local observation traces up to action time, any deterministic local detector makes the same action in both worlds. Then an additional observation (remote probe/redundant task) or a cost-conservative abstain state is necessary.
- **Negative-result value:** establish the device/workload boundary where resource metrics cannot improve timeout decisions, or identify which single metric recovers the full policy's gain. This can remove unjustified ML complexity.
