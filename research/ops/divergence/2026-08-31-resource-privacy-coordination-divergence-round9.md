# Divergence Packet: 2026-08-31 resource, non-personal privacy, and local coordination

## Decision investigated

Whether a low-cost, non-production edge FYP can make a defensible contribution outside the killed sensing, adaptation, OTA, storage, redundancy, acceptance-sampling, and generic offloading families by using **resource management, non-personal confidentiality, or local multi-node coordination**.

The permitted operational setting is deliberately narrow: a university/lab maintainer coordinates non-personal, proprietary batch jobs across 2--3 local edge nodes.  A missed job means a labelled bench run or report must be repeated; a false admission causes an avoidable deadline breach.  No personal data, production service, or safety actuation is claimed.  Exact board inventory remains [GAP], so the only admissible hardware statement is that two additional affordable SBCs *could* be purchased; a containerised trace replay is the minimum pre-purchase gate.

## Search boundary

Searched 2026-08-31 for primary/official 2024--2026 work on `local differential privacy resource allocation edge computing scheduling`, `private resource advertisement distributed scheduling edge`, `private set intersection edge IoT event deduplication`, `offline access revocation intermittent IoT edge capability token`, `privacy utility aware schedule publishing`, `DP budget scheduling edge`, `Raspberry Pi edge cluster scheduling`, and `CRDT escrow resource allocation IoT edge`.

Excluded by instruction before search: biometrics; unlabeled TTA/risk; active sensing and calibration; camera/CSI/UWB/magnetometer/mmWave/gas diagnosis; outage/storage/OTA/I2C; redundant execution; acceptance/transfer release; active-learning queues; and generic quantisation verification.  I also reject a cloud/vehicle/LLM simulation relabelled as an SBC study.

## Top two formalizations

### PLAR-Safe: private load advertisement as a useful boundary experiment, not a scheduling claim

- **[D] Decision.** At arrival time \(t\), coordinator selects \(a_t \in \{\text{reserve}(1),\ldots,\text{reserve}(m),\text{local},\text{defer}\}\) for a fixed, non-preemptive job class with an externally timed deadline.  A deadline miss is independently observable from process start/finish logs, not inferred from a model score.
- **[A] Assumptions.** Nodes are honest-but-curious; each knows its actual binary feasibility \(z_i\) under a pre-registered resource envelope.  It releases exactly one \(\epsilon\)-LDP randomized-response bit \(r_i\) per epoch.  Jobs, duration distribution, clock-error bound, losses, and the privacy adjacency (change in one node's feasibility bit) are fixed in advance.  No claim covers malicious reports, adaptive correlation, or an unlimited release history.
- **[T] Test/claim.** Derive the strongest one-sided deadline-risk upper bound obtainable from \(r_{1:m}\), \(\epsilon\), and a specified prior-free or declared-prior model; measure the risk--utility curve.  The positive claim is only accepted if it beats neither an unavailable oracle nor a weaker baseline, but is **not reproduced by the exact-posterior/lower-confidence-bound policy using the same \(r\)**.  This last condition is expected to fail for a purely static setting.
- **Observable outcome.** Deadline miss, deferral rate, successful jobs, reporting bytes/energy, and a defined disclosure experiment that distinguishes \(z_i=0\) from \(z_i=1\).  DP is a formal bound on the single release, not a claim that no operational inference remains.
- **Counterexample.** Two controllers that see the same randomized-response vector and know the same model cannot choose differently because of an alleged new ``edge insight.''  The Bayes/robust policy is equally informed.  Repeated reports also compose privacy loss; ignoring this makes any apparent positive result invalid.
- **Negative-result value.** A reproducible privacy--deadline feasibility frontier answers a practical scope question: under which \(\epsilon\), job slack and report rate does privacy-constrained coordination become necessarily vacuous?  It would prevent the much stronger but false claim that LDP load sharing ``safely schedules'' arbitrary edge jobs.

### SCHED-PUB-STREAM: schedule privacy versus reservation correctness

- **[D] Decision.** Before a fixed reservation horizon, a node chooses `publish exact slot`, `publish a perturbed availability envelope`, or `withhold/defer`; a receiver decides `reserve / wait`.  The outcome is an actual double-reservation or missed known deadline.
- **[A] Assumptions.** Jobs have a declared duration and release time; the attacker knows the scheduling rule and public job durations but not one private priority/urgency attribute; no side channel beyond released messages.  This is deliberately close to Basmer et al.'s inverse-scheduling attacker.
- **[T] Test/claim.** A survivor would need to show that streaming message causality and the safety invariant create a different feasible-set problem from static PUP, while Basmer-style perturbation plus standard time-bounded leases cannot match the privacy/correctness pair.  This is **unverified**.
- **Observable outcome.** Trace-verified double reservation, deadline loss, byte cost, and attack success under the preregistered attacker only.
- **Counterexample.** If a static perturbed schedule or a normal lease yields the same reservation decisions, `streaming local edge` is mere deployment.  If a message contains enough timing/order for the inverse attack, calling it encrypted transport does not repair the privacy endpoint.
- **Negative-result value.** It can produce a documented collision: a teaching bench that demonstrates why privacy-preserving schedule publication does not automatically provide online coordination privacy.  It is not currently a thesis lead.

## Decision

**PIVOT.** Do not promote an ordinary resource allocator, privacy budget scheduler, PSI deduplicator, revocation scheme, or bounded-counter demo.  The only remotely defensible lead is **PLAR-Safe as a narrow, Amber, explicitly negative-capable privacy--deadline boundary experiment**, and it must first survive a validation round against: (1) the exact-posterior/lower-confidence baseline on the same LDP messages; (2) Zhou et al.'s full threat/model/evaluation chain; (3) the 2026 LDP resource-sharing paper's exact claim; and (4) a concrete, non-personal confidentiality owner/adversary.  If any equally informed baseline reproduces it, record the feasibility frontier as a negative appendix and KILL it as the FYP topic.
