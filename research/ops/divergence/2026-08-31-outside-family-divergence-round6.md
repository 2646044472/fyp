# Divergence Packet: 2026-08-31 outside-family edge decision mechanisms

## Decision investigated

Find a new, low-cost, non-personal-data edge FYP direction *outside* the already-audited biometric, adaptive/virtual sensing, reference-calibration/camera-health, OTA/lifecycle, outage provenance, redundancy, storage/power-recovery, and generic reliability families.

The feasible operating envelope used here is a one-year FYP, a runnable bench demonstration by 2026-12, inexpensive self-purchased hardware, no production service and no safety actuation.  A candidate below is a hypothesis to be falsified, not a novelty claim.  All novelty status is Amber until the coordinator completes component-collision, exact-claim-collision, and boundary/impossibility audits.

## Search boundary

Primary-source search, 2024-01-01 to 2026-08-31, covered four distinct mechanisms:

1. on-device learning and human label requests;
2. deployment/runtime semantic preservation under quantisation;
3. label-free post-deployment performance monitoring; and
4. active acoustic sensor self-diagnosis.

I deliberately excluded a new sensor modality, an MCU deployment result, compression, fusion, fixed thresholds, or a different public dataset as a contribution.  I also treated a result that only says a direction is impossible under its declared observations as useful rather than as a failure to report.

## Top two formalizations

### UPM-EdgeBound: a useful negative-result boundary

- **[D] Decision:** `continue`, `request review`, or `suspend` a non-personal local record stream.
- **[A] Allowed action:** choose one of those three outputs; review produces a bounded number of delayed labels.  No adaptation, remote probe, reference target, second sensor, or intervention is allowed in the impossibility part.
- **[T] Target:** target error/risk of a fixed classifier over the next finite window, or a non-vacuous upper bound on it.
- **Observable outcome:** (O=(x_{1:n}, f(x_{1:n}), r_{1:n})), where (r) is bounded resource telemetry.  The candidate explicitly does *not* observe (y_{1:n}), target (p(y|x)), an independent reference, or labels before deciding.
- **Counterexample:** construct environments (E_0,E_1) with identical (p(O)), but choose a different label mechanism on a nonzero-probability input region so target error differs.  Any policy seeing only (O) has the same output distribution in both; therefore it cannot have a valid, discriminating distribution-free target-error certificate.  This is the edge-specific instantiation of the identification boundary reported by Garg et al., not a claim that all useful alarms are impossible.
- **Negative-result value:** it prevents a demonstrably unsupported “device-transfer reliability certificate,” and it turns the next design choice into a measurable question: which extra witness (delayed labels, restricted shift model, independently measured factor, or a new experiment) breaks the indistinguishability?
- **Why it is not yet PROMOTE:** the general impossibility is already known.  It only becomes an FYP candidate if the coordinator identifies a *new, narrow, practically motivated observation restriction* plus an informative minimal-witness theorem/protocol that does not repackage known label-shift/SJS assumptions.

### QNN-DecisionGuard: formal positive claim and direct collision

- **[D] Decision:** release a binary edge inference as `same-side` relative to a specified reference decision, otherwise `unknown`.
- **[A] Allowed action:** run a statically verified integer arithmetic guard using the deployed graph and input; no second board or repeated model execution is needed.
- **[T] Target:** the sign of (s_{\mathrm{FP32}}(x)-\tau) versus (s_{\mathrm{INT}}(x)-\tau) under a declared operator/rounding/overflow model.
- **Observable outcome:** compiled quantised weights/scales, the deployed supported-op graph, current input, and static arithmetic semantics.  It cannot certify sensor truth, ground-truth class, unsupported kernels, memory corruption, or preprocessing mismatch.
- **Counterexample / kill:** if an existing sound quantisation-bound verifier proves at least the same sign preservation on every test input, then any proposed guard is derivative.  If two physical runtimes differ outside the specified semantics, the formal claim fails rather than becoming a hardware reliability contribution.
- **Negative-result value:** a clean outcome is a released test suite showing the input-space fraction where quantisation *does not* permit a sign guarantee; that is an honest deployment boundary.  It is still not sufficient as a thesis because QEBVerif/Dang et al. already occupy its core verification mechanism.
