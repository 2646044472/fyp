# Divergence Packet: 2026-08-29 Outside Sensing - Lifecycle, Network, and Security

## Decision investigated

Find candidates outside the already killed sensing/wake-up, model-selection, vibration/ToF, timeout-transfer, provenance, and physical-watermark families.  This packet asks whether a cheap, non-personal edge deployment can make a new *decision* about a radio loss, device lifecycle state, or local data lifecycle.  It does **not** infer novelty from a Raspberry Pi, LoRa module, secure element, or a new trace.  All surviving language is **Amber** pending component, exact-claim, and boundary audits.

## Search boundary

Searches on 2026-08-29 covered 2024--2026 primary work in four mechanisms: (i) LoRa loss/jamming/collision handling and geographically diverse gateways; (ii) firmware attestation and edge-worker enrollment; (iii) edge--cloud continuity under disconnection; and (iv) intermittent-power recovery, flash faults, and cryptographic deletion.  I inspected the task, input assumptions, action, evaluation, and limitations where full primary text was available.  Paywalled/full-text-inaccessible papers are explicitly marked `[GAP]`; their abstracts are not treated as proof of a gap.

Deliberately excluded: any claim whose actionable mechanism is an adaptive sensor wake, sampling rule, confidence-based abstention, sensor-condition map, resource-stress timeout, post-hoc log provenance, or a fresh physical challenge.  The existing register shows each has already reached KILL.

## Top two formalizations

### LDR: loss-decision relevance under multi-receiver observation

- `[D]` A planned report has latent class \(Z\in\{\text{link-specific degradation},\text{receiver-local interference/collision},\text{common-mode loss}\}\).  Receiver \(i\) emits \(O_i\) only when it decodes a packet: receipt bit, packet sequence, RSSI/SNR, and local timestamp.  The policy observes \(O=(O_1,O_2,\text{recent missing sequence pattern})\) and chooses \(A\in\{\text{duplicate once},\text{retain/wait},\text{inspect}\}\).  The cost is declared before experiments: unrecovered gap, unnecessary airtime, and unnecessary inspection.
- `[A]` The two receiver locations have a documented but not perfect diversity relation; impairment cells are generated without using target-cell outcomes for policy thresholds; common-mode loss is admissible.
- `[T]` **Target empirical claim, Amber:** relative to all fixed policies and one-receiver classifiers selected on source cells, the pre-specified two-view policy reduces held-out action loss or abstains correctly (`unknown`) in a non-vacuous set of impairment cells.  This is falsified by a fixed duplication rule or two-receiver OR delivery matching it.
- Observable outcome: receipt-vector sequence, retransmission cost, deliberately labelled but benign closed-bench impairment class, and blinded technician-action cost.  No adversary identity is inferred.
- Counterexample: if a broad interferer, correlated deep fade, or transmitter failure suppresses both receivers, \(O\) cannot distinguish the listed latent causes.  The only honest output is `unknown`; claiming more is `[KILL]`.
- Negative-result value: a compact empirical indistinguishability map identifies which low-cost gateway observables are insufficient for a causal maintenance decision and whether a second receiver is only a diversity baseline.

### EDL: what low-cost edge deletion can honestly claim

- `[D]` A record \(x_t\) is encrypted under epoch key \(k_t\).  The release decision sees host-side filesystem state, key-store location, and a local readback result.  The target property is non-recoverability to a declared adversary after retirement, not a generic assertion that bytes disappeared.
- `[A]` The data were encrypted before the release decision; the adversary and key-store trust boundary are fixed before testing.  A removable-card controller may retain inaccessible physical blocks.
- `[T]` **Boundary target, Amber:** if the epoch key is recoverable from the same removable storage, no host-side deletion/readback test can prove non-recoverability against card imaging.  If a non-exportable separate key store is present, deletion can support only the stated cryptographic-adversary property.
- Observable outcome: controlled recovery attempts against synthetic files, key-location audit, and post-retirement readback; counterexample is a recoverable key, plaintext cache, or an adversary stronger than the declared cryptographic model.
- Negative-result value: the project can produce a reproducible claim-scope matrix rather than a false “secure erase” demo.  Positive value requires a real hardware root-of-trust and an auditable direct-neighbor distinction, currently `[GAP]`.
