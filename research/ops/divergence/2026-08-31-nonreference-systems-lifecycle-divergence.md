# Divergence Packet: 2026-08-31 Non-reference Edge Systems, Lifecycle, and Integrity

## Decision investigated

Whether a low-cost, non-personal edge FYP can still make a defensible decision contribution after excluding biometric/palm work, generic adaptive sensing, reference-target/chart/buffer scheduling, outage-journal provenance, generic I2C recovery, ToF/vibration, camera counting, generic stress/timeout studies, and model deployment/compression.  This pass deliberately searches device lifecycle, data integrity, intermittent systems, networking, privacy/security, and technician workflows rather than relabeling a sensing threshold as research.

No candidate below is a novelty claim.  All positive language is Amber until component-collision, exact-claim-collision, and boundary/impossibility audits are complete.

## Search boundary

Recent primary and official sources from 2024--2026 were inspected for five distinct mechanisms:

1. independently observed firmware-update recovery on cheap devices;
2. local detection of a silently wrong deterministic computation without a cloud replica;
3. whether a configuration/calibration transition can justify joining two edge record segments;
4. what a removable-media retirement workflow can honestly claim about reuse; and
5. offline ownership/control transfer when a device lacks a current trusted time or rendezvous service.

The following were explicitly excluded before candidate generation.  PFIP 2025 and the intermittent-computing literature already cover transactional power-failure recovery and checkpoint correctness.  AutoPKI 2024 and NIST SP 1800-36 already cover IoT onboarding, trust transfer, attestation, and lifecycle posture.  Digital Calibration Certificate (DCC) work already provides signed calibration metadata and offline/asynchronous exchange.  Autonomous decommissioning and media-sanitization work directly constrain wipe/decommission narratives.  These sources create direct baselines; their presence is not treated as evidence that no narrower task can exist.

## Top two formalizations

### RWE: recovery action from an independently observed update state

- **[D]** Let the latent pre-action state be \(F \in \{\text{nominal},\text{partial image},\text{stale manifest},\text{corrupt boot metadata},\text{recovery-config mismatch},\text{post-boot mutable-app fault}\}\).  The device exposes \(O_d\): self-reported version, verified-boot result, and update status.  A separately powered reader exposes \(O_e\): hash of a named immutable boot region and bytes/hash of a named update manifest.  The technician chooses \(A\in\{\text{release},\text{recover},\text{unknown}\}\).  The predeclared loss penalizes false release, unnecessary recovery, and elapsed intervention time.
- **[A]** The external reader's target regions and wiring are fixed before data collection; fault injection cannot alter the reader; the study is non-adversarial and only covers the listed benign update/recovery faults.  The golden state is recorded outside the policy.
- **[T]** **Amber empirical claim:** on held-out boards/update cells, a policy using \((O_d,O_e)\) achieves strictly lower false-release loss at equal intervention time than the self-report/verified-boot policy, full reflash, and always-unknown.  The reader must add information beyond a manifest signed and checked by immutable verified boot.
- **Observable outcome.** Golden flash/manifest state, action actually taken, recovery time, energy, and whether a deterministic local test record is correct after release.  The local test is a scoring oracle, not a claim of security against a compromised runtime.
- **Counterexample.** A correctly measured boot region and manifest coexist with a later mutable application/configuration failure.  Then \((O_d,O_e)\) cannot justify a global statement that future records are correct.  The honest output is either scope-limited release or `unknown`.
- **Negative-result value.** A compact state-observability map can show exactly whether a $5 external witness has any decision value over verified boot.  If not, it prevents an attractive but redundant hardware demo from being misreported as a security contribution.

### SDC-X: deciding whether a deterministic local result is retainable

- **[D]** A public deterministic input \(x\) has independently stored digest \(h(x)\).  Main board \(P\) returns \(y_P\); a cheap companion board \(Q\) returns \(y_Q\).  A seeded fault variable \(F\) may alter state after input validation and before output commit.  The policy observes \((h(x), y_P, y_Q, \text{energy},\text{latency})\) and chooses \(A\in\{\text{retain},\text{recompute},\text{unknown}\}\).
- **[A]** The experiment represents only declared injected corruptions, not measured consumer-board fault incidence.  Inputs and implementation binaries are version-pinned; the two computations share neither output memory nor the fault injector.  A common input or specification bug is explicitly admissible as an unresolvable case.
- **[T]** **Amber empirical claim:** under a pre-registered fault distribution and a fixed energy/time ceiling, heterogeneous re-execution changes the held-out false-accepted-result frontier against same-board rerun, output checksum, and always-unknown.  Any benefit must persist when policy thresholds are frozen before target cells.
- **Observable outcome.** Exact reference result from an offline gold implementation, hidden seeded-fault label, energy/time, action loss, and cases in which both boards agree on a wrong output.
- **Counterexample.** A corrupt but hash-consistent shared input, deterministic common implementation defect, or post-comparison corruption causes agreement without correctness.  Therefore the mechanism cannot certify general correctness; it can at most protect the registered independent-execution fault class.
- **Negative-result value.** If ordinary checksum/retry matches the proposed scheme, the negative result identifies that diversity has no decision value under the tested faults.  If common-mode cases dominate, it defines the missing independent observable needed before any stronger claim.

## Decision

**PIVOT.** Do not promote a primary direction from this packet.  **RWE** and **SDC-X** are the only two Amber hypotheses that merit an adversarial exact-neighbor audit because each uses a narrowly different observation/action endpoint and has an honest negative path.  **DCC-SPLIT**, **REUSE-WIPE**, and **OFT** should be treated as likely KILL controls: current primary/official work already occupies their ordinary mechanisms, and their remaining claims are either routine reporting or an information boundary without a new intervention.  No candidate has passed the three required audits.
