# 从“看起来有用”到可被否定的经济故事

最后更新：2026-08-21。本文件不替项目编造商业需求。它规定在何种证据下，才可以说受控现场需要一个掌纹 edge 核验器；在什么结果下，应该放弃这个应用故事。

## 1. 必要性不是“掌纹比卡片先进”

候选系统不是替换一切门禁，而是一个窄的双步骤核验：

`工单/实体卡/受控 QR 提出被授权者 claim -> 本地 palm 1:1 确认 -> 最小审计事件或明确 fallback`

这样做的前提不是“澳门没有掌纹”，也不是用掌纹判断任何人的法律/劳动资格。唯一可成立的必要性必须来自以下三个可验证命题之一：

| 命题 | 可能的现有损失 | 这个系统真正改变什么 | 不能宣称什么 |
| --- | --- | --- | --- |
| A. 人和凭证会脱钩 | 关键区域/工具需要人工确认、事后难追溯或有例外处理 | 仅把被出示的 claim 与当场呈现者作 `1:1` 确认 | 不证明法律身份、授权本身或违法行为 |
| B. 有限的本地连续性有价值 | 现场网络/后台短暂不可用时，需要人工暂停或事后补记 | 在预先同步的、有限的授权名册上本地给出 allow/retry/fallback | 不替代后台撤销、全局权限和网络安全 |
| C. 原始生物帧的集中流动是不可接受的成本 | 组织不希望为低频核验建立图像上传、集中保存和大规模访问流程 | 默认本地 capture/match，日志只留匿名结果和设备状态 | 不自动获得不可逆、不可关联或法律合规性质 |

只有 A/B/C 至少一项在目标现场有量化证据，且对方仍接受 biometric/fallback 的代价，才有“需要”。若卡/PIN/人工流程已低摩擦、网络稳定且组织拒绝生物特征，结论应是**不部署**，不是继续优化模型。还要先做一次 `make / buy / do nothing` 比较：商用 palm print/vein 终端已公开组合 RGB/IR、距离、QR 与门禁接口；学校的 Pi 原型不是产品替代品，除非能以实测说明它在哪个固定硬件预算、资料边界或实验透明度下提供不同价值。

## 2. 经济价值应计算的不是“掌纹市场规模”

对一个具体现场，以一个月为单位，先记录以下输入而非假设收益：

| 输入 | 如何取得 | 现在的值 |
| --- | --- | --- |
| `N`：受限核验次数 | 门禁/工具日志或一周人工计数后外推 | 未知 |
| `r_exception`：需要人工核验或事后修正的比例 | 标记卡丢失、代刷疑虑、无网、审计缺口等原因 | 未知 |
| `t_manual`：每个例外的人工分钟 | 现场 shadowing 或负责人估计，记录区间 | 未知 |
| `C_labor`：含管理成本的人工分钟成本 | 由组织提供；没有就不填货币 | 未知 |
| `L_event`：已发生且可证明的单次事件损失 | 只接受已审计事件；不能用新闻或臆测 | 未知 |
| `r_residual`：新流程仍留下的例外/风险比例 | pilot 数据，而非模型 accuracy | 未知 |
| `C_deploy`、`C_operate` | 设备、登记、培训、清洁、支持、替代流程 | 未知 |
| `C_existing`、`C_switch` | 现有 card/QR/人工流程，以及商用终端报价/集成/切换成本 | 未知 |

在获得这些输入后，才可做透明的**场景计算**：

`monthly_manual_cost = N * r_exception * t_manual * C_labor`

`monthly_avoided_manual_cost = monthly_manual_cost * (1 - r_residual)`

`monthly_net_value = monthly_avoided_manual_cost + documented_avoided_event_value - C_operate - amortized(C_deploy)`

这不是预测式 ROI：所有变量必须给范围、来源和敏感性。例如 `r_exception` 很低或 `t_manual` 很短时，即使模型优秀也没有经济必要性；反之，经济价值也不能替代对 BPCER、IAPMR、隐私和 fallback 的约束。

## 3. 访谈与流程观察设计

在老师批准和受访者同意后，做 5--10 个半结构访谈，优先覆盖设施/物业、承办商、安保/值班和数据保护/IT 角色。不要问“你会不会买掌纹”，而要重建最近一次真实流程。

1. 请描述最近一次临时人员进入受限区域或领取关键工具的全过程。身份 claim 由什么产生？谁决定授权？
2. 当卡片、QR、工单、人或网络发生例外时，谁花多少时间处理？过去一个月大致多少次？
3. 哪些事件必须能够事后关联“人、工单/工具、时间”？哪些日志本来就有？
4. 哪些情况必须立即放行、必须拒绝、必须改人工处理？可接受的 p95 等待时间和重试次数是多少？
5. 手套、污渍、水分、伤口/贴布、工具搬运或无障碍需求会怎样影响实际采集？不要要求受访者披露医疗细节。
6. 他们愿意存什么、不愿意存什么？是否必须提供 card/PIN/人工 fallback？谁能访问、保留多久？
7. 网络失效时当前流程是什么？离线 allow 是否被允许，还是只能记录后人工复核？
8. 如果系统仅减少原始帧上传但引入登记、清洁、支持和拒绝成本，是否仍值得？为什么？
9. 现有 card/QR/人工流程或可采购 palm terminal 为什么不够？请比较实际采购、集成、支持、资料保留和故障处理成本，而不是只比较识别 accuracy。

记录角色、场景、流程节点、原话的可核对摘要和不确定度，不记录姓名、雇主、掌纹或敏感劳动身分。把“没发生”“不允许”“没价值”当作重要结果。

## 4. 采用/退出门槛

| 闸门 | 继续条件 | 停止或转向条件 |
| --- | --- | --- |
| 需求 | 至少两个不同角色确认 A/B/C 中一项发生，并能给出频率、时间或审计证据 | 只有泛泛的“更方便/更安全”，无真实流程和可量化代价 |
| 合规与接受度 | 明确目的、同意/替代路径、删留规则和人工责任人可被写成 demo requirements | 目标场所不接受 biometric，或不能提供公平有效 fallback |
| 可用性 | bona fide 的 retry、BPCER、p95 interaction time 在现场预算内，且例外流程可完成 | 低攻击通过率只是靠常规用户不断重采或被锁在外面获得 |
| 安全 | 在预冻结 protocol 的未见 session/PAIS 中，主方法较 B0/B1 有净 IAPMR/APCER 改善 | 没有简单 PAIS 能通过 B0，或收益只出现在已见材料/随机切分 |
| edge | 本地断网行为、恢复和最小日志都能按角色要求实测 | 使用 cloud/后台才能正确决策，或 Pi 长期热/传感故障不可接受 |

## 5. 对论文叙事的影响

若通过以上闸门，论文可以说：**我们针对一个由实地 workflow 确认的低频受控核验任务，量化主动多传感 gate 在安全、可用性和 edge 资源上的 trade-off。**

若需求闸门不通过，正确论文是：**在低成本 Pi 采集盒中，报告 contactless palm verification 的质量、攻击和资源测量边界。** 不能再在摘要中放经济价值或澳门需求。

NIST SP 800-63B-4 的 biometrics 指导面向网络数字身份，而非澳门实体门禁法律；本项目只借用其审慎原则：生物比较有 FMR/FNMR 与主动冒充风险，替代非生物路径和敏感资料保护应是系统设计的一部分，不能用“本地生物识别”代替完整认证保证。参见 [NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b.html)。
