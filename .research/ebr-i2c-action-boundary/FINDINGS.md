# EBR-AIM: I2C action boundary on a low-cost edge sensor node

## Summary

Superseded as an FYP primary direction on 2026-08-31. EBR-AIM remains only a named-device, benign recovery observability/conformance experiment. Linux and vendor documentation, 2024-2025 recovery patents, and the 2026 observability preprint occupy the generic recovery and monitoring families. A policy cannot claim to beat an equally informed active router given the same probe, action set and costs; the residual is a finite hardware boundary or replication result.

## Findings

### Occupied mechanisms [K]

- Linux kernel GPIO fault injection documents wire states and incomplete transfers, including an incomplete write-byte case. The same documentation warns that additional SCL clocks after an incomplete write can produce an unintended register write. Current Linux source exposes `i2c_generic_scl_recovery` and a nine-clock recovery constant.
- TI SCPA069 (July 2024, pp. 5-7) and NXP AN10148 describe stuck-bus recovery using clocking, STOP and reset/power actions.
- US20250068503A1 (published 2025-02-27, description paragraphs 122-152 and claims 8-9) discloses status monitoring, target identification, reset/power isolation, retry and notification for an I2C bus.
- SentryBus (arXiv v1, 2026-08-17, pp. 1-7) is a generic edge reliability-observability neighbor. It is evidence against claiming a new monitor, not evidence that the present finite endpoint is novel.

### Observation boundary [K]/[C]

For the registered fault family, a prefix such as `SCL=1, SDA=0, NACK/timeout` can be generated by more than one hidden cause. Therefore a passive prefix cannot be assumed to identify the best recovery action. The finite counterexample and loss comparison are [C] until measured on the frozen topology.

### Candidate claim [C]/[GAP]

On held-out target, timing and fault cells, a countable independent probe may lower preregistered post-action loss relative to a matched staged driver with the same probe budget. If it does not, the study reports the ambiguity map and simple-policy sufficiency instead. Exact endpoint collision after the final protocol search remains [GAP].

## Strongest objection

The patent and standard recovery procedures may already imply the same action-selection endpoint. The pilot must therefore compare against the staged driver, disclose all probe cost, measure collateral writes and keep hidden fault labels out of the policy. A failure on any of these checks demotes the work to replication/negative boundary.

## Feasibility boundary

A one-controller/two-target benchtop using ESP32/RP2040-class GPIO, an optional Linux edge host, cheap I2C breakouts, pull-ups, a target power switch, MOSFET clamps and a low-cost logic analyzer is sufficient for the minimum experiment. Exact SKU, instrument access, delivery and budget are still [GAP] and must be cleared before purchase. No production, personal-data or safety-actuation deployment is required.

## Open questions

- Which target has a documented read-only or sacrificial register map and deterministic reset behavior?
- Can the chosen controller expose an independent probe without sharing the injected-fault label?
- What deadline and loss weights are defensible for a local lab-maintenance record?
- Does the exact-claim search, rerun after protocol freeze, find an identical finite utility/ambiguity endpoint?
